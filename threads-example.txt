Thread #1
Kalian pernah gaa baca sebuah function, terus mikir:
“Ini function sebenarnya cuma melakukan hal sederhana… tapi kenapa cara nulisnya serumit ini? 😭”
Logic nya sebenarnya ngga terlalu sulit, tapi pas ngeliat nested if, else, loop, dan berbagai kondisi di dalamnya, kita jadi harus mikir berkali kali buat memahami apa yang sebenarnya dilakukan oleh function tersebut.
Nah, ternyata ada istilah khusus untuk hal seperti ini.
Namanya Cognitive Complexity

Thread #2
Cognitive Complexity adalah ukuran seberapa sulit sebuah kode untuk dipahami manusia.
Jadi, fokusnya bukan cuma apakah kode ini bisa dijalankan, tapi juga seberapa besar effort yang dibutuhkan developer untuk memahami logic di dalamnya.
Makin banyak nested condition, loop, dan struktur logic yang membuat kita terus berpikir ulang, makin tinggi juga cognitive complexity nya.
Dan ini penting, karena kode yang sulit dipahami akan lebih sulit di maintain maupun dikembangkan oleh developer lain.

Thread #3
Coba amati kode di bawah ini.
Aku kasih contoh 2 block kode dengan cognitive complexity yang berbeda.
Padahal, tujuan kedua function tersebut sama, tapi function kedua membutuhkan effort lebih besar untuk dipahami, karena kita harus terus mengikuti nested condition dan berbagai kemungkinan jalur logic.
Itulah salah satu gambaran sederhana dari cognitive complexity.
Jadi bukan sekedar jumlah baris kode, tapi seberapa sulit otak kita mengikuti alur logic-nya.

Thread #4

Jadi kita bisa tahu function mana yang terlalu kompleks atau bagian mana yang perlu di refactor
Dengan begitu, kita nggak cuma memastikan kode kita works, tapi juga tetap readable dan maintainable.

Kalian pernah ga sih ngalamin hal kaya diatas? Udah jadi developer tapi masih bingung soal Authentication vs Authorization

Thread #2
Disini gw coba jelasin pake bahasa bayi "Apa itu mereka berdua" dan "Apa perbedaannya"
Authentication = “Who are you?” → sebuah proses untuk memverifikasi identitas pengguna.
Authorization = “What are you allowed to do?” → sebuah proses untuk menentukan hak/akses pengguna setelah terautentikasi.
Singkatnya: Authentication identifies you;
Authorization decides your permissions.
Masih bingung? Ini penjelasan singkatnya

Thread #3
Authentication adalah proses untuk memastikan identitas seseorang sebelum dia boleh masuk ke dalam suatu sistem. Sederhananya, sistem ingin memastikan bahwa “kamu benar benar orang yang kamu bilang sebagai dirimu”
Misalnya, seseorang mengatakan dirinya Budi. Sistem akan checking informasi yang diberikan untuk memastikan identitas tersebut benar. Jadi, authentication berhubungan dengan identitas, bukan dengan apa yang boleh dilakukan seseorang.
Authentication menjawab pertanyaan: “Kamu siapa?”

Thread #4
Contoh implementasi authentication yang paling sederhana adalah login menggunakan email dan password.
User
↓
Masukkan email + password
↓
Frontend mengirim data ke server
↓
Server mencari user berdasarkan email
↓
Server memverifikasi password
↓
Password benar?
├── Ya → User dianggap terautentikasi
└── Tidak → Login ditolak 

Thread #5
Dalam aplikasi web modern, setelah berhasil login, server biasanya memberikan session atau token (misalnya JWT). Token/session tersebut dapat digunakan untuk mengenali user pada request berikutnya.
Contoh sederhana dengan JWT:
Method: POST
Endpoint: /login
{
"email": "ilham@example.com",
"password": "password123"
}
Server memverifikasi kredensial tersebut, lalu mengembalikan:
{
"token": "eyJhbGciOiJIUzI1NiIs..."
} 

Thread #6
Authorization adalah proses untuk menentukan apa saja yang boleh dilakukan oleh seseorang setelah identitasnya sudah diketahui. Sederhananya, sistem sudah tahu “kamu siapa”, lalu sistem menentukan “apa yang boleh kamu lakukan”.
Jadi, authorization bukan tentang membuktikan identitas / login / register, tetapi tentang hak akses atau permission yang dimiliki seseorang.
Kalau dibuat sangat sederhana: authorization itu proses untuk menjawab pertanyaan “Kamu boleh ngapain aja disini” 

Thread #7
Misalnya sebuah aplikasi memiliki dua jenis user:
Admin → boleh melihat, menambah, mengubah, dan menghapus user.
User → hanya boleh melihat data.
Ketika user mencoba menghapus data:
User
↓
"Siapa kamu?"
↓
Authentication
↓
"User ID 123, role: user"
↓
Authorization
↓
"User boleh menghapus data?"
↓
No ❌
↓
403 Forbidden
Sedangkan jika yang melakukan adalah admin:
Admin
↓
Authentication
↓
"Admin ID 1, role: admin"
↓
Authorization
↓
"Admin boleh menghapus data?"
↓
Ya ✅
↓
Data dihapus
